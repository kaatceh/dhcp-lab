# Лабораторна робота: Налаштування та дослідження протоколу DHCP

## 1. Мета лабораторної роботи
Ознайомитися з протоколом DHCP (Dynamic Host Configuration Protocol), навчитися налаштовувати DHCP-сервер у конфігураційному файлі `/etc/dhcp/dhcpd.conf`, дослідити роботу мережних утиліт та засвоїти навички створення тестової документації (Test-case та Defect Report).

---

## 2. Результати теоретичної підготовки

* **IP-адреса на мережному рівні моделі OSI:** Унікальний логічний ідентифікатор пристрою на 3-му (мережному) рівні моделі OSI. Використовується для адресації та маршрутизації пакетиків даних між різними підмережами.
* **Статичне та динамічне налаштування IP-адрес:**
  * *Статичне налаштування* — IP-адреса та параметри мережі призначаються адміністратором вручну і є постійними.
  * *Динамічне налаштування* — параметри мережі та IP-адреса виділяються автоматично спеціалізованим сервером на обмежений час (lease time).
* **Протокол DHCP та алгоритм DORA:** Автоматизує процес конфігурації. Взаємодія клієнта і сервера базується на чотирьох етапах:
  1. **DHCPDISCOVER** — широкомовний пошук доступних DHCP-серверів клієнтом.
  2. **DHCPOFFER** — пропозиція вільної IP-адреси та параметрів від сервера.
  3. **DHCPREQUEST** — запит клієнтом обраної IP-адреси.
  4. **DHCPACK** — підтвердження виділення адреси сервером та завершення налаштування.
* **DNS (Domain Name System):** Служба для перетворення текстових доменних імен у числові IP-адреси і навпаки.

## 3. Виконання практичної частини
Практична частина виконувалася в середовищі Linux (Ubuntu) за допомогою контейнеризації Docker на базі macOS.

### 3.1. Встановлення DHCP-сервера та утиліт
Завантажено та встановлено пакет `isc-dhcp-server` та необхідні мережні утиліти:
```bash
apt-get update && apt-get install -y isc-dhcp-server net-tools iputils-ping nano

```

### 3.4. Конфігурація головного файлу `dhcpd.conf`

Створено та налаштовано конфігураційний файл `/etc/dhcp/dhcpd.conf`:

```text
default-lease-time 600;
max-lease-time 7200;
option subnet-mask 255.255.0.0;
option broadcast-address 172.17.255.255;
option routers 172.17.0.1;
option domain-name-servers 172.17.0.1, 8.8.8.8;
option domain-name "mydomain.example";

subnet 172.17.0.0 netmask 255.255.0.0 {
    range 172.17.0.50 172.17.0.100;
}

```

Створено файл оренди та надано відповідні права доступу, після чого запущено сервер у режимі логування:

## 4. Тестова документація (QA)

### 4.1. Test-case (Варіант: Додавання статичного запису в ARP-таблицю)

* **ID тест-кейсу:** TC-NET-003
* **Назва:** Перевірка додавання статичного запису в ARP-таблицю та пінг пристрою
* **Передумови:** Наявність прав суперкористувача, активний мережний інтерфейс.
* **Кроки виконання:**
1. Переглянути поточну ARP-таблицю: `arp -a`
2. Додати статичний запис: `sudo arp -s 192.168.1.100 aa:bb:cc:dd:ee:ff`
3. Виконати пінг: `ping 192.168.1.100`


* **Очікуваний результат:** Запис успішно додано з міткою постійного (PERM), зв'язок опрацьовується коректно без зайвих широкомовних запитів.

### 4.2. Defect Report (Звіт про дефект)

* **ID дефекту:** DR-DHCP-001
* **Назва дефекту:** Конфлікт IP-адрес при наявності двох активних DHCP-серверів у локальній підмережі.
* **Серйозність (Severity):** Major
* **Пріоритет (Priority):** High
* **Опис проблеми:** У разі одночасної роботи роутера та локально налаштованого `isc-dhcp-server` у межах одної підмережі, клієнти отримують IP-адреси від того сервера, чий пакет `DHCPOFFER` надійшов першим. Це призводить до розбиття мережі на сегменти та втрати стабільного зв'язку.
* **Кроки відтворення:** Запустити власний DHCP-сервер у мережі, де вже працює DHCP на роутері; підключити нового клієнта (`dhclient`).
* **Фактичний результат:** Клієнт отримує випадкову адресу з діапазону локального сервера замість шлюзу мережі.
* **Очікуваний результат:** У сегменті мережі має функціонувати лише один авторизований DHCP-сервер.
